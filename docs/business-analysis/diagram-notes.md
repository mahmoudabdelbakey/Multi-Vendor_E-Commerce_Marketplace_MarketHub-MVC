# Diagram Notes

Use these notes when reviewing diagrams with the team.

1. System Context: defines external actors/systems and the system boundary.
2. Use Case: defines user goals, not implementation details.
3. Activity: describes the end-to-end review analysis flow and decision points.
4. DFD: focuses on movement and storage of information.
5. Domain/Class: identifies core business objects and relationships.
6. ERD: translates business data concepts into relational persistence structures.
7. Deployment: shows where API, model artifact, database, and clients run.
8. Architecture/Component: shows software boundaries and dependencies.
9. ML Pipeline: separates training/evaluation from runtime prediction.
10. State: shows the lifecycle of a review through validation, processing, and analysis.
